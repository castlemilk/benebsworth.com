# Chapter author’s self-critique

## Set up the read

Open the supplied URL or find the chapter through `/learning/`. Note the build and viewport. For a rerun, use the previous reader tasks and save any heading fragments being renamed. Read the opening question before the answer key.

## Reader checklist

- [ ] **Work the example.** Cover the conclusion. Recompute the decisive result. For a measured comparison, put the two source rows side by side, including the sampled population, conditions, unit and boundary. Identify which change the comparison can isolate. If a qualifier matters, find it again in the figure, narration and quiz feedback. For a qualitative mechanism, trace what changes and predict an observable consequence.
- [ ] **Find the evidence.** Start at the question with glosses closed. If the evidence is farther down the page, choose a visible shortcut or contents entry from its wording alone. Record which label tells a first-time reader where to go. Needing to guess the section or already know the answer merits a repair.
- [ ] **Answer at the destination.** Follow each named case and its claim from the opening to the figure, closing decision and recorded introduction. From the evidence, choose an option or explain why the choice is still open. If only a test protocol is justified, ask which test to run. A purchase question needs comparable results, which may be explicitly illustrative.
- [ ] **Read the figures in sequence.** Cover the captions and try the intended inference at phone width. If a randomly chosen style obscures the comparison, sketch the next candidate using the same data. If unrelated explanations repeat the same layout, check what another treatment would reveal. Preserve shared axes and labels across deliberate comparisons.
- [ ] **Read the chart at 390 px and on desktop.** Cover the caption. With the chart at rest, read the smallest decisive mark, its comparator, both row labels and their unit. Compare the displayed numbers with the series. Does a positive component read as zero, or do unequal values look equal? Try a finer unit or more significant digits. Check for clipped SVG text and ellipses that hide the identity of a row.
- [ ] **Read a middle section and the final decision.** Say what each lets you predict or diagnose. Compare one with a completed neighbour. Open a gloss by keyboard and touch. Which misconception does it resolve? Follow its figure link and a contents link. Check the title and legend are visible below the sticky header and breadcrumb.
- [ ] **Take the self-test blind.** Solve each transfer question. Find what changed from the worked example and check the prose, open glosses, figures and audio for the answer. At a threshold, distinguish a tie from a win. Hide the prompts and try choosing by wording alone. Check wrong-answer feedback. Run the [quiz checks](../SKILL.md#review-the-worked-example-before-recording) on the web quiz and exported written copy. Compare the flagged question numbers, correct choices and worked answers, including the flashcard for a revised key.
- [ ] **Follow old and exported links.** For a renamed heading or figure, open the old fragment in a fresh tab, then try the new contents link. Both should reach the intended target. In `index.md`, try changed prose and gloss links. If Markdown exports a figure as an image, a link needs a real local anchor or the canonical HTML figure URL.
- [ ] **Seek into the audio.** Play across a slide change, then seek backwards into an uncued turn where the speaker introduces a different quantity. Point to the evidence for that sentence in the frame. Record the timestamp and the missing evidence if it still shows the previous idea. On a phone, read the deciding labels with the text still in reach. If playback starts at zero, check the preview host’s byte-range response.

## Close the review

Mark each item **pass**, **needs repair**, **unverified** or **not applicable**. Give reproducible evidence. If the browser test stops at a clipped label, exercise quiz feedback and transcript playback separately before recording their status. Prioritise wrong or pre-revealed answers, unreachable evidence and unreadable deciding values. Trace the failure to the responsible passage, figure, renderer or export.

In an authoring pass, repair it, rebuild and repeat the same reader action at the same viewport. Close a finding once the reader can complete the task. When a premise changes, recheck dependent figures, glosses and answer keys. In a review-only pass, describe the repair and how to verify it.

Keep a finding to one line, for example, “Compare batch-one bars at 390 px → B’s 33.6 µs label disappears → place the value outside the bar → awaiting phone retest.” Hand off one strength to preserve, the most consequential open finding and the checks actually run. For model comparisons, credit any reviewer-supplied cases and use recorded usage for cost claims.
