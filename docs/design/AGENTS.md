# Design documentation guidance

This guidance applies only within `docs/design/`. It supplements rather than
replaces the repository root instructions. It grants no permissions and does
not change approval, security, release or sharing requirements.

- Read `LEARNINGS.md` and the relevant existing design contract before editing.
  Keep established decisions separate from proposals and dated evidence.
- Preserve recovered originals, prompts, receipts and manifests byte-for-byte.
  Add corrections or later release receipts outside historical source packets;
  never present an inferred prompt or missing artifact as recovered.
- Record exact source revision and evidence kind: source-only, DOM test,
  automated browser, inspected render or live verification. Do not convert one
  into a stronger claim. A screenshot alone does not accept interaction states.
- Keep subject identity, original source labels, taxonomy status and operational
  claims distinct. Generated art is metaphor, not evidence of factual coverage.
- Recheck active owners and current host contracts before documenting integration.
  Use isolated scopes; preserve dirty checkouts and unrelated work. Draft PRs,
  private references, public repository source and deployed URLs are different
  states. A public repository's draft branch is not private.
- Retain existing tests and normal hooks. Preserve partial-recovery caveats and
  unresolved acceptance decisions when updating a completion receipt.
