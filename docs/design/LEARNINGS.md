# Blog design and artwork learnings

Consolidated 17 November 2026 against released commit
`e1c0f0a4c9ac4d7d189542e7c71abf274cc0977e`. This is a dated decision
record, not a claim that every separate workbench has shipped.

## Established boundaries

- Preserve the editorial reading shell outside Hardware. The knowledge console
  alone uses the SPEC-01 skin. Root `AGENTS.md` remains authoritative for SDK
  imports and style order; this record introduces no framework migration.
- The research folio uses warm paper/graphite, editorial type and restrained red.
  About's later clean professional direction supersedes its earlier handwritten
  concept. Hiking retains its natural trail identity. Do not flatten these into
  one repeated card template. See `PERSONAL-FOLIO.md` and `VISUAL-REVIEW.md`.
- Generated subject art is illustrative metaphor, not scientific evidence,
  biography, geographic truth, article coverage or taxonomy adoption. Preserve
  official marks and original ART04 assets separately.
- The 50-image expansion covered 14 then-existing topic keys and 36 proposed
  topics at briefing time. Those historical labels are not a current content
  inventory. Runtime graph IDs and route availability come from the current
  provider, never from an illustration filename.

## Lessons from the private asset library critique

Taste, Impeccable and Deslop reviews converged on specific source-confirmed
issues. The private reference was corrected at revision
`165702ad958c0c1f6734202abb9ce7c305b6386b`; it is not the production graph or
an integrated version of the independent editorial workbench.

- A toggle's accessible name describes a stable setting; `aria-pressed` conveys
  state. Use “Dark preview background”, not a name that alternates to describe
  the opposite action while pressed describes the current state.
- Give repeated downloads distinct subject-specific names. Announce new-tab
  behavior. Retain native links, labelled filters, result counts and reset.
- Normalize punctuation and meaningful topic aliases in search. Test aliases
  together with collection filters and zero-result recovery, not in isolation.
- Separate a readable subject heading from its complete original source record.
  Improve hierarchy without deleting provenance, changing artwork order or
  quietly rewriting original labels.
- Put usage limitations near the art. Avoid redundant numbered eyebrows and
  overclaiming scientific precision or perfectly clean alpha cutouts.
- Distinguish source/DOM evidence from fresh rendered, mobile, keyboard,
  assistive-technology and contrast acceptance. The private-reference fixes
  passed independent source/DOM review; no fresh native visual audit is claimed.

The unchanged 50 image destinations, original labels and 58 protected files,
including five ZIPs, were checked during that private-reference correction.
Speculative gallery reorder and preview rescaling were not adopted.

## Source recovery and publication

[PR 157](https://github.com/castlemilk/benebsworth.com/pull/157) preserves six
original ART04 concepts. Missing original prompts/settings and companion SVGs
must not be reconstructed as if recovered.

[PR 164](https://github.com/castlemilk/benebsworth.com/pull/164) preserves four
complete source packets and batch 04's explicitly partial recovery: 17 PNGs,
ten prepared prompts and four actual call receipts. Later actual prompts,
settings, rejected opaque revision and final cumulative patch remain missing.
A prepared prompt is not evidence that a generation call used it.

The 316-file delivery verifier, 50 selected-original receipt matches and
independent PNG decoding establish byte provenance, not artistic acceptance or
exclusive rights. Keep originals immutable; record derivatives separately.

PR 164 is merged and publicly released at the baseline above. The source
branch was already public on GitHub before merge; draft status was never a
privacy boundary. Deployment adds URLs for files under `public/`, even without
runtime imports. Batch 04 remains docs-only partial recovery. Historical
“draft only” statements inside recovered packets describe their original
handoff stage, not current authorization or release status.

## Runtime and acceptance boundaries

[PR 162](https://github.com/castlemilk/benebsworth.com/pull/162) delivered the
knowledge console; [PR 163](https://github.com/castlemilk/benebsworth.com/pull/163)
corrected view symbols and caption contrast. Preserve existing source inspection,
real study routes and keyboard behavior. Later integration must explicitly define
independent graph-root/selection and URL/history semantics with the owners; these
are not claimed as existing host behavior. Do not replace the live provider with
an older isolated model merely because its tests pass.

At this baseline, model/views/editorial/motion PRs 158–161 and the ActionNode
packet are distinct integration candidates. Recheck their owners and current
state before work; this document does not accept or merge them. Native tests
for an isolated component do not prove host-provider compatibility.

The [release run](https://github.com/castlemilk/benebsworth.com/actions/runs/44065944954)
passed 3,334 unit tests and 160 browser tests. Live build-info and representative
public original bytes matched the release. That evidence does not accept every
concept for runtime use or validate all scientific metaphors.

## Next review decisions

- Decide runtime adoption and sizing of individual expansion illustrations from
  actual light/dark and narrow render evidence, with alpha/fringe inspection.
- Integrate model, views, components, motion and ActionNode through explicit
  current-provider adapters and native host journeys, under coordinated owners.
- Share semantic/accessibility principles across blog, Atlas and Omega without
  mechanically unifying their distinct identities or authority models.
