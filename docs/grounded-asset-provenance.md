# Grounded Forms fixed-artwork asset provenance

## Scope and identity

30 reviewed artworks; 90 unchanged SVG masters; 90 transparent lossless 480 × 480 WebP thumbnails and 90 transparent lossless 960 × 960 previews. Masters remain 900 × 900 with viewBox `0 0 900 900`. Six works require 320px display width; the remaining 24 require 240px. Thumbnails are discovery aids, not an assertion that intricate details remain legible below those minimum widths.

This pilot is separate from procedural/tunable study generation. No source packet was rewritten, no palette was recolored, and no build, browser, deployment, installation or network fetch was needed for import. The existing PR #147 merge hold is unchanged.

Canonical slug mapping removes only the initial two-digit directory-style prefix from the original manifest ID. Titles never replace IDs: Nodal membrane retains `degenerate-membrane`. Batch ID, original source ID, numbered directory ID and revision remain recorded verbatim in the catalogue. Public data contains no private filesystem paths.

## Provenance and scientific scope

Original authored vector constructions, not copied or traced reference imagery. Exact packet captions, full scientific basis paragraphs and limitations are preserved. Source citations are transcribed from the reviewed packet and are not newly fetched or independently certified by this import. Prior scientific and visual checks are source-packet evidence, not new experimental validation. The importer checks file integrity, dimensions, safety, alpha and derivative reproducibility; it does not certify biological species, structural safety, real material properties or physical simulations. Search metadata is hand-curated from positive subject matter, never extracted from exclusions such as “not a Chladni plate” or “not a stable Turing pattern.”

## Lossless repository source transport

`assets/grounded/manifest.json` and its 46 content-addressed `parts/*.br.b64` files are the committed source transport. Each of the 30 Brotli streams contains the original light, dark and mono SVG bytes concatenated in that order. The unchanged catalogue supplies each original length, SHA-256 and download URL. There is no archive filename, extraction path, SVG optimizer, tracing step, palette conversion, geometry rewrite or procedural regeneration. Existing source, attribution and license terms are unchanged; this transport introduces no new license grant.

The 90 original SVGs total **8,570,142 bytes**. Their Brotli streams total **767,259 bytes**; the largest artwork stream is **144,756 bytes**. Streams are split at **32,768 compressed bytes**, yielding 46 base64 text files totalling **1,023,114 bytes**. The largest text file is **43,693 bytes**. The 15,523-byte manifest records stream and part lengths and SHA-256 hashes, plus the existing pinned catalogue digest. Total committed manifest plus encoded source parts: **1,038,637 bytes**. Compression is deterministic with the same Node/Brotli runtime; a future compressor version need not produce identical compressed bits because the committed stream hashes and original SVG hashes remain authoritative.

`node scripts/prepare-grounded-artwork.mjs` validates the catalogue pin, part hashes and canonical base64, bounded Brotli output, exact original hashes and every existing public output. It restores missing masters without changing a byte and renders missing WebPs through the existing importer's `renderWebp` function. Every rendered byte count and SHA-256 must match the unchanged catalogue before that artwork's missing files are written. A renderer change fails rather than updating the catalogue or accepting different downloads. Existing files with wrong bytes fail rather than being silently overwritten. A warm run skips rendering only after every source and public hash passes.

Expansion accepts only catalogue-derived output paths and SHA-256-derived part filenames. It rejects extra manifest keys, unsafe paths, symlinked files/directories, nonregular files, oversized files, missing/truncated/mutated parts, extra public files and output-count drift. Native decompression is capped at the three catalogue lengths (at most 3 MiB), compressed streams at 1 MiB and each text read at 43,693 bytes. Artwork processing and WebP rendering are sequential, keeping at most one artwork's source and pending outputs in memory. No network, new dependencies, hosted asset service, credentials or permission change is involved.

`public/artwork/grounded/` is generated and ignored by Git. npm `prebuild`, `predev`, `pretest` and `pretest:watch`, Task build/default, build/clean, dev, unit/watch and the credential-free `remote:check` lane prepare it before consumers run. Preparation is outside test workers, so parallel tests never race to populate the repository. Task's build fingerprint includes the committed source packet and both preparation/importer scripts. The existing postbuild checks still validate all original download identities and derivative hashes in the emitted site.

```sh
# Restore missing files, validating all existing source/output hashes first.
npm run artwork:prepare

# Read-only source and complete prepared-output verification.
npm run artwork:check

# Package only already-reviewed, complete public assets into immutable source parts.
# Existing changed source parts/manifests are refused, never overwritten.
node scripts/prepare-grounded-artwork.mjs --pack

# Isolated temporary-directory tests, including fresh expansion of all 270 files.
node --test scripts/tests/prepare-grounded-artwork.test.mjs
```

The source packaging suite also runs in ordinary Vitest through `lib/grounded-artwork/packaging.test.ts`. It checks byte-for-byte restoration of all 270 outputs, dimensions/alpha, deterministic packing, warm and partial preparation, renderer drift, corrupted existing files, catalogue mutation, transport corruption, bounded decompression, unsafe metadata, symlinks, FIFO/nonregular files, unexpected files and build/test/dev hook ordering. It does not establish Next build, browser, CI or publication acceptance. The existing PR #147 hold remains unchanged.

## Reproducible verification

Recorded renderer: sharp 0.34.5, libvips 8.17.3, librsvg 2.61.2, libwebp 1.6.0.

Existing installed `sharp` renders unchanged SVGs at density `72 × size / 900`, then resizes exactly to 480 or 960 and encodes WebP with `lossless: true, effort: 6`. No background is flattened. Both alpha-channel presence and at least one fully transparent pixel are required. Asset hashes make output sensitive to renderer changes, which intentionally fail reproducibility checks until reviewed.

From repository root:

```sh
# Prepare generated files, then verify catalogue, every hash/byte count/dimension, SVG safety, alpha,
# and freshly regenerated thumbnail + preview bytes (no original packets needed).
node scripts/prepare-grounded-artwork.mjs
node scripts/import-grounded-artwork.mjs --check

# Recheck immutable inventory, all source authorities and source manifest hashes,
# regenerate assets, and byte-compare both metadata and assets without writing.
node scripts/import-grounded-artwork.mjs --inventory <reviewed-inventory.json> --check

# Initial/reviewed reimport (does not rewrite the input packets).
node scripts/import-grounded-artwork.mjs --inventory <reviewed-inventory.json>

# Focused negative and asset-integrity tests only.
node --test scripts/tests/import-grounded-artwork.test.mjs
```

The original inventory records source locations and must remain locally available for source-packet checks. It is never published. Its pinned digest makes an altered inventory a re-review event. Metadata changes require reviewing and updating the catalogue pin intentionally. XML parsing plus element/attribute allowlists reject malformed documents, scripts, images, foreign content, events, entities, external references and duplicate IDs. Verification rejects duplicate identities, unexpected/stale asset files, altered source bytes or authorities, and output mutations. No source packet is regenerated.

Both npm and Task postbuild pipelines check the generated search index and all 30 emitted routes, 90 SVG masters and 180 WebP fallbacks before release stamping. The importer regression suite joins the ordinary unit suite; existing original-study hashes and asset tests remain unchanged.

The approximately 1,000-piece plan includes these 30 grounded subjects. The earlier 36-pattern expansion is superseded as a planning queue, not deleted source. Existing live studies, the 18 additions in the held PR147–149 stack, and six separate object/place candidates are preserved independently. Palette and size variants never increase the distinct-artwork count. Further batches require new scientific/visual review and a reviewed inventory update, not loosening the current 30-item import receipt.

Source preparation and tested derivatives do not establish browser acceptance or publication. Record exact-head CI and visual evidence separately; release remains dependent on resolving the PR147 merge hold through the existing workflow.
